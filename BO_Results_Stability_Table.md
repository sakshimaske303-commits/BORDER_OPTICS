Six results in this study changed value between an earlier extraction/analysis and the current, frozen one. Each reversal was caught by this project's own completeness checks or by external review, diagnosed to a specific, named cause, and resolved by a full re-run — not patched over. This table lists all six in one place. Five of the six results reversed exactly once and stayed there; the sixth (row 6) is the one exception, disclosed as such rather than folded into the same "resolved and done" pattern as the other five.

## What stayed stable throughout

For contrast: H3's night-lights-proximity result crossed the same window-dependent line in every version of this paper, unchanged by any of the six rows above — significant full-year (p < 0.0001), null summer-matched (p = 0.266). It's included here to show the reversals above were specific, diagnosed data or code defects (or, in row 6's case, a specific and disclosed side effect of an unrelated data-quality fix), not a pipeline that reshuffles every number on every run.
